# robot-client

Godot 4 + C# клиент онлайн-игры про роботов в общем городе, собранном из открытых данных OpenStreetMap (OSM).

## Статус

**Этап «каркас + сетевой срез + визуализация».** Godot 4 Mono-проект (без ассетов) с сетевым модулем `NetworkClient`: подключение к robot-srv, `auth`, приём `welcome`/`error`/`snapshot`, отправка `input`. `Main` создаёт мир процедурно (плоскость `PlaneMesh`, робот-куб `BoxMesh`, камера, HUD-`Label`), читает WASD/стрелки и шлёт `input` не чаще серверного тика (20 Гц), а робот двигается строго по серверным снапшотам — без CharacterBody3D, ассетов и клиентского предсказания.

- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — архитектура клиента и план этапов.

## Стек

- Godot 4 (Mono / .NET)
- C# (.NET 8)
- WebSocket для связи с сервером (протокол v1, см. репозиторий robot-srv)

## Ассеты

Игровые ассеты (модели `.glb`/`.fbx`, текстуры, аудио) и OSM-дампы **не хранятся в репозитории**. Они поставляются из внешнего источника (репозиторий ассетов / CDN). Подробности — в политике ассетов (ARCHITECTURE.md) и `.gitignore`. Проект не требует бинарных ассетов для сборки и запуска.

## Запуск

### Сервер

```bash
cd robot-srv
cargo run    # слушает $ROBOT_SRV_ADDR, по умолчанию 127.0.0.1:8080
```

Проверка: `curl http://127.0.0.1:8080/healthz`.

### Клиент

```bash
cd robot-client
# 1. Открыть проект в Godot 4 (Mono): выбрать project.godot в Project Manager
#    или запустить редактор: godot --editor --path .
#    Редактор синхронизирует RobotClient.sln/.csproj и соберёт C#-код.
# 2. Запустить сцену scenes/Main.tscn (F5).
```

Ожидаемый вывод в консоли: подключение, отправка `auth`, приём `welcome`
(или понятной `error` от сервера). На экране — плоскость мира, оранжевый
куб-робот и HUD (tick, позиция, курс, состояние, скорость).

### Управление

| Клавиши | Действие |
|---|---|
| `W` / `↑` | вперёд |
| `S` / `↓` | назад |
| `A` / `←` | влево |
| `D` / `→` | вправо |

Ввод шлётся серверу не чаще `tick_rate` (из `welcome`); позиция робота
обновляется строго по серверным `snapshot` (сервер авторитетен, prediction
в этом срезе нет).

Параметры сцены `Main` (в инспекторе, export-параметры):

| Параметр | Default | Назначение |
|---|---|---|
| `ServerUrl` | `ws://127.0.0.1:8080/ws` | адрес WebSocket сервера |
| `AuthToken` | (пусто) | заглушка токена, авторизация позже |

### Проверка модуля NetworkClient без редактора

`NetworkClient` — чистый C#-модуль без зависимостей от Godot-нод, поэтому
его можно скомпилировать и прогнать консольным приложением на .NET 8.

## Ограничения Godot Mono/.NET

- Нужна сборка Godot 4 **с поддержкой .NET (Mono)** и установленный **.NET SDK 8+**; без них C#-скрипты не компилируются, редактор не запустит сцену.
- Версия `Godot.NET.Sdk` в `RobotClient.csproj` должна соответствовать версии редактора. При расхождении редактор предложит обновить файлы проекта (синхронизация `.sln`/`.csproj`).
- Первый запуск компилирует C# (`dotnet`); кэш `bin/`, `obj/`, `.godot/` и `.mono/` в git не хранятся (см. `.gitignore`).
- `NetworkClient` использует `System.Net.WebSockets.ClientWebSocket` — работает на десктопе и в редакторе. Для экспорта на web (HTML5) потребуется Godot `WebSocketPeer`; в этом срезе не реализовано.
- В Godot C# `[Export]`-параметры видны в инспекторе только после успешной сборки проекта.

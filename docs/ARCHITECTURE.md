# Архитектура robot-client

Версия: 0.2 (сетевой срез + визуализация)
Дата: 2026-09-28

## 1. Цель

Клиент онлайн-игры на Godot 4: игрок управляет роботом в общем городе на базе OSM. Сервер авторитетен (см. репозиторий robot-srv); клиент отвечает за ввод, визуализацию, сглаживание сетевого потока (prediction/interpolation) и интерфейс.

## 2. Стек

| Слой | Выбор | Обоснование |
|---|---|---|
| Движок | Godot 4 (Mono) | сценарный граф, физика, тулинг |
| Язык | C# (.NET 8) | типизация, производительность критичных путей |
| Сеть | WebSocket, протокол v1 | общая спецификация с robot-srv |
| Рендер | Forward+ (десктоп), Mobile (позже) | баланс качества и производительности |
| Сериализация | JSON (совместимо с robot-srv v1) | общий формат сообщений |

## 4. Камера: FPS / third-person

- `PlayerController` (CharacterBody3D) — движение робота по вводу.
- **FPS**: Camera3D привязана к голове робота, захват мыши, лёгкий head-bob.
- **Third-person**: SpringArm3D + Camera3D — орбита, коллизии плеча, зум колесом.
- Переключение режима — клавиша (например, `C`), ввод не теряется.
- Режимы камеры не влияют на сеть: серверу всегда уходит одинаковый `input`.

## 5. Сетевой слой

- Транспорт: WebSocket (`wss`); адрес/порт — из конфига или ответа сервера.
- Подключение: `auth` (токен, версия клиента) → `welcome` (id сессии, tick rate).
- Keepalive: `ping`/`pong` 0.2 Гц; реконнект с экспоненциальным backoff (план).
- Сообщения протокола v1 (JSON): конверт `{v, type, seq, ts, payload}`.
- Сетевой менеджер (чистый C#) не зависит от Godot-нод: снапшоты приходят в игровой слой через события.

### Текущий срез

- `NetworkClient` шлёт `auth` и `input` (`{ "move": { "x": .., "z": .. } }`), принимает `welcome`, `error`, `snapshot`.
- `Main` читает WASD/стрелки и шлёт `input` **не чаще** серверного `tick_rate` (из `welcome`).
- Робот-куб позиционируется строго по серверным `snapshot` — prediction/interpolation в срезе нет.
- Мир отрисовывается процедурно (`PlaneMesh` + `BoxMesh`), камера и HUD-`Label` создаются в коде; ассеты не требуются.

## 6. Prediction / interpolation

Цель — отзывчивое управление и плавное отображение чужих роботов при 20 Гц сервера.

- **Client-side prediction** (свой робот): локальное продвижение по `input` в интервалах между снапшотами; откат (reconciliation) при расхождении больше порога.
- **Interpolation** (чужие роботы): буфер снапшотов 100–150 мс, интерполяция позиции и поворота между двумя последними снапшотами.
- **Extrapolation** (опционально): предсказание движения при потере снапшотов.
- Ключевые метрики (RTT, джиттер, расхождение позиций) — в debug-HUD.

## 7. Навигация

- `NavigationServer3D` / `NavigationAgent3D` — для NPC, автономных роботов и «ведомых» целей.
- Маршруты от сервера (граф OSM → `route(a, b)`) транслируются клиентом в путь: ломаная точек + дистанция; перерисовка при `order.updated`.
- При наличии тайлов карты маршрут накладывается на дорожную сеть.

## 8. Рендер карты

- Данные карты приходят с сервера (`map.meta`, тайлы/геометрия) — клиент не хранит OSM-дампы локально.
- Векторные тайлы → меши/коллайдеры, подгрузка по секциям вокруг игрока.
- Опционально: сервер отдаёт статику для коллизий, клиент использует её как источник NavMesh.

## 9. Политика ассетов

**В репозитории запрещены любые бинарные игровые ассеты и OSM-дампы:**

- модели: `.glb`, `.fbx`, `.dae`, `.obj`, `.blend`;
- текстуры: `.png`, `.jpg`, `.jpeg`, `.tga`, `.exr`, `.hdr`, `.ktx2`;
- аудио: `.wav`, `.ogg`, `.mp3`;
- карта: `.osm`, `.osm.pbf`, `.pbf`;
- кэш движка: `.godot/`, `.import`.

Правила:

1. Ассеты живут во внешнем репозитории ассетов / CDN и скачиваются при сборке.
2. Git LFS не используется.
3. В git — только исходники: `.cs`, `.gd`, `.tscn`, `.tres` (конфиг), `project.godot`.
4. Папка `assets/` игнорируется в git.

## 10. План этапов

| Этап | Содержание | Критерий готовности |
|---|---|---|
| **0 — Bootstrap** | архитектура, план | docs приняты |
| **1 — Каркас** (готово) | проект Godot + C# solution, структура, input-map | проект открывается, есть сцена |
| **2 — Контроллер** (частично) | движение робота, камеры FPS/third-person, переключение | управление работает; в срезе — ввод + позиция из снапшотов |
| **3 — Сеть** (частично) | WebSocket, auth/welcome, heartbeat, реконнект | подключение к серверу, поток снапшотов; heartbeat/reconnect — план |
| 4 — Pred/Interp | prediction своего робота, интерполяция чужих | двое роботов плавно двигаются |
| 5 — Карта | приём тайлов, рендер дорог, коллизии | карта сервера отображается |
| 6 — UI | HUD заказов, мини-карта, инвентарь, магазин модов | полный цикл заказа из UI |
| 7 — Полировка | анимации, звук, эффекты, offline-режим | сборка-кандидат |
| 8 — Интеграция | совместные тесты с robot-srv, beta | публичная beta |

Порядок этапов синхронизирован с robot-srv: сетевой слой — после готовности серверной части протокола.

## 11. Глоссарий

- **Snapshot** — серверный слепок состояния на тик.
- **Client-side prediction** — локальный прогноз по собственному вводу.
- **Interpolation buffer** — буфер снапшотов для плавного отображения.
- **Reconciliation** — синхронизация предсказания с серверной истиной.
